# Критерии успеха и результаты проверки

Кейс формулирует критерий так: агент отвечает на большинство вопросов по отчёту
и не выдумывает. Кейсодатель на QA добавил, что отказ при отсутствии данных это
правильный ответ, а метки банка пересчитывать нельзя. Из этого мы вывели четыре доли
и судью: вторую модель, которая оценивает каждый ответ по рубрике из списка ниже. Ошибки разной цены считаем отдельно: пропущенный красный фактор стоит денег,
ложная тревога стоит времени.

## 1. Критерии

| Критерий                       | Как считается                                                 | Порог |
| ------------------------------ | ------------------------------------------------------------- | ----- |
| Подтверждаемых ответов         | проверки кодом пройдены и судья поставил не меньше 4 из 5     | ≥ 0,8 |
| Корректных отказов             | вопросы, где данных в отчёте нет: агент отказал и не домыслил | ≥ 0,9 |
| Выдуманных фактов              | судья нашёл в ответе факт, которого нет в данных инструментов | 0     |
| Пропущенных критичных факторов | в карточке есть красный фактор, агент его не назвал           | 0     |
| Судья по рубрике               | средний балл от 0 до 5                                        |       |
| Неверных ссылок                | число верное, адрес поля не тот                               |       |

Судья обнуляет ответ, если пропущен красный фактор, назван факт, которого нет
в данных или дан ответ по существу там, где данных нет. Снижает балл: отказ при наличии данных −2,
число по судам без роли и периода −2, метка пересчитана или объяснён её расчёт −2,
нет даты отчёта −1, вердикт без условий −1, ложная тревога на чистой карточке −1,
ярлык на контрагента −1. Тон и длину судья не оценивает.

## 2. Как проверяли

Эталон: 219 вопросов на 77 карточках. Начинали с 50 вопросов на 12 карточках, за ночь
на 6.09 довели до текущего размера. Карточки выбраны под сломанные места в данных:
банкротство при зелёных метках, исключение из ЕГРЮЛ при нуле негативов, блокировка
счетов при низком риске, метки, противоречащие друг другу, чистая компания, компания
с 1744 производствами и тремя разными числами судов, редкие секции. По разметке:
28 «можно работать», 27 «нужна дополнительная проверка», 22 «в отчёте есть факты,
требующие особого внимания»; три терминальных, десять ИП.

| Тип вопроса                    | Сколько | Что проверяет                                                   |
| ------------------------------ | ------: | --------------------------------------------------------------- |
| карточка, «проверь компанию»   |      77 | вывод совпал с разметкой, критичные факты названы, дата отчёта  |
| ответ есть в данных            |      44 | нашёл поле, назвал число с ролью, периодом и датой              |
| ответа в данных нет            |      31 | отказал, не домыслил, назвал, чего не хватает                   |
| нужен вывод из полей           |      38 | собрал факты из нескольких разделов в действие для пользователя |
| сравнение нескольких компаний  |      11 | вывод по каждой компании, без баллов и рейтингов                |
| диалог                         |       9 | два-пять ходов в одной сессии, память и смена темы              |
| посторонний ввод               |       9 | ругань, инъекции, «покажи промпт»: отбить, не трогая отчёт      |

Ни одно число в эталоне не придумано: кейсы составлены по выдаче инструментов
и перепроверены отдельным скептиком.

Сначала код проверяет обязательные подстроки, запрещённые формулировки, валидность
адреса поля, дату отчёта и совпадение вывода; для сравнения ещё вывод по каждой
компании и запрет рейтингов, для постороннего ввода ноль вызовов инструментов.
Потом судья получает вопрос, ответ агента, выдачу инструментов и карточку и ставит
балл по рубрике. Ответ считается подтверждаемым, только если пройдены оба слоя.
Судья это qwen3-235b, специально другое семейство моделей, чтобы агент не судил сам
себя.

Прогнали семь версий промпта. Ниже цифры финальной, на целевой дешёвой модели
gpt-oss-20b: с 7.09 она стоит на стенде. Сильная gpt-oss-120b прогнана на том же
эталоне для сравнения.

## 3. Результаты

Финальная версия, целевая модель, 219 вопросов:

| Критерий | Значение | Порог |
|---|---:|---:|
| Подтверждаемых ответов | 146 из 178 · 82 % | ≥ 0,8 |
| Корректных отказов | 27 из 31 · 87 % | ≥ 0,9 |
| Выдуманных фактов | 0 из 219 · 0 % | 0 |
| Пропущенных обязательных фактов в карточке | 0 из 77 · 0 % | 0 |
| Отклонённых ссылок | 2 из 219 · 0,9 % | |
| Судья по рубрике | 4,58 из 5 | |

Три порога из четырёх выполнены. Отказы недотягивают: из 31 вопроса, где данных
в отчёте нет, четыре ответа не прошли проверки кодом. Выдумок в них нет, это
формулировки: агент отказывает, но не всегда называет, чего именно не хватает.

Проверки кодом по типам вопросов: карточка компании 77 из 77, посторонний ввод
9 из 9, сравнение 10 из 11, ответ по данным 36 из 44, отказ 27 из 31, вывод
из нескольких полей 30 из 38, диалог 6 из 9.

Сравнение с предыдущей версией на том же эталоне и том же судье: подтверждаемых
было 54,5 %, стало 82 %; пропуск обязательных фактов в карточке был 10 из 77, стал 0;
выдумки были 6,4 %, стали 0; судья был 4,04, стал 4,58. Улучшение получено переносом
выбора фактов, расчётов и проверки ответа в код: правкой промпта эти ошибки
не устранялись.

Устойчивость: 88 сценариев прогнаны по три раза на двух моделях, 528 прогонов.
На целевой модели проверки кодом прошли 245 из 264, судья поставил 4 и выше в 259
из 264, и в 76 группах из 88 успешными оказались все три повтора. Всего на финальной
сборке 1 044 живых прогона, включая многоходовые диалоги.

Кроме эталона: 417 локальных тестов без сети и модели, 2 200 проверок инвариантов
детерминированных ответов на всех 200 компаниях без нарушений, 23 сценария HTTP
и потоковой выдачи на публичном стенде.

Скорость на целевой модели: медиана успешного ответа 1,9 секунды, 95-й процентиль
4,2. На сильной модели вдвое дольше при сопоставимом качестве, поэтому на стенде
стоит дешёвая.

## 4. Что дальше

Цифры выше это регрессия, а не независимая приёмка: вопросы использовались при поиске
и исправлении ошибок, поэтому корректная формулировка статуса — готовность
к контролируемому пилоту с проверкой ответов. К приёмке: независимая проверка новых
вопросов и обезличенных отчётов специалистами банка; собственный список обязательных
фактов под каждый тип вопроса вместо общего; разметка ответов руками для сверки
с судьёй; длительная нагрузка и наблюдение за задержками. Порог входа: ноль
пропущенных критичных факторов и ноль выдуманных на свежей выгрузке.
