# Критерии успеха и результаты проверки

Кейс формулирует критерий так: агент отвечает на большинство вопросов по отчёту
и не выдумывает. Кейсодатель на QA добавил, что отказ при отсутствии данных это
правильный ответ, а метки банка пересчитывать нельзя. Из этого мы вывели четыре доли
и судью: вторую модель, которая оценивает каждый ответ по рубрике из списка ниже. Ошибки разной цены считаем отдельно: пропущенный красный фактор стоит денег,
ложная тревога стоит времени.

## 1. Критерии

| Критерий                       | Как считается                                                 | Порог |
| ------------------------------ | ------------------------------------------------------------- | ----- |
| Подтверждаемых ответов         | проверки кодом пройдены и судья поставил не меньше 4 из 5     | ≥ 0,8 |
| Корректных отказов             | вопросы, где данных в отчёте нет: агент отказал и не домыслил | ≥ 0,9 |
| Выдуманных фактов              | судья нашёл в ответе факт, которого нет в данных инструментов | 0     |
| Пропущенных критичных факторов | в карточке есть красный фактор, агент его не назвал           | 0     |
| Судья по рубрике               | средний балл от 0 до 5                                        |       |
| Неверных ссылок                | число верное, адрес поля не тот                               |       |

Судья обнуляет ответ, если пропущен красный фактор, назван факт, которого нет
в данных или дан ответ по существу там, где данных нет. Снижает балл: отказ при наличии данных −2,
число по судам без роли и периода −2, метка пересчитана или объяснён её расчёт −2,
нет даты отчёта −1, вердикт без условий −1, ложная тревога на чистой карточке −1,
ярлык на контрагента −1. Тон и длину судья не оценивает.

## 2. Как проверяли

Эталон: 219 вопросов на 77 карточках. Начинали с 50 вопросов на 12 карточках,
за ночь на 6.09 довели до текущего размера. Карточки выбраны под сломанные места
в данных: банкротство при зелёных метках, исключение из ЕГРЮЛ при нуле негативов,
блокировка счетов при низком риске, метки, противоречащие друг другу, чистая компания,
компания с 1744 производствами и тремя разными числами судов, редкие секции.
По разметке: 28 «можно работать», 27 «нужна дополнительная проверка»,
22 «в отчёте есть факты, требующие особого внимания»; три терминальных, десять ИП.

| Тип вопроса                    | Сколько | Что проверяет                                                   |
| ------------------------------ | ------: | --------------------------------------------------------------- |
| карточка, «проверь компанию»   |      77 | вывод совпал с разметкой, критичные факты названы, дата отчёта  |
| ответ есть в данных            |      44 | нашёл поле, назвал число с ролью, периодом и датой              |
| ответа в данных нет            |      31 | отказал, не домыслил, назвал, чего не хватает                   |
| нужен вывод из полей           |      38 | собрал факты из нескольких разделов в действие для пользователя |
| сравнение нескольких компаний  |      11 | вывод по каждой компании, без баллов и рейтингов                |
| диалог                         |       9 | два-пять ходов в одной сессии, память и смена темы              |
| посторонний ввод               |       9 | ругань, инъекции, «покажи промпт»: отбить, не трогая отчёт      |

Самый большой раздел это суды, 22 вопроса: самое запутанное поле отчёта и первое,
о чём доуточняют по словам кейсодателя. Дальше реестр и метки 19, финансы 16,
решения с целью проверки 15, приставы 12, редкие секции 12, инъекции 11, отказы 10.
Ожидаемый вывод по каждой карточке проставлен до прогонов. К каждому вопросу записаны
ожидаемый ответ по данным инструментов, поле-источник, обязательные и запрещённые
формулировки. Ни одно число в эталоне не придумано: кейсы составлены по выдаче
инструментов и перепроверены отдельным скептиком, из 94 сгенерированных два отброшены
как дубли.

Сначала код проверяет обязательные подстроки, запрещённые формулировки, валидность
адреса поля, дату отчёта и совпадение вывода; для сравнения ещё вывод по каждой
компании и запрет рейтингов, для постороннего ввода ноль вызовов инструментов.
Потом судья получает вопрос, ответ агента, выдачу инструментов и карточку и ставит
балл по рубрике. Ответ считается подтверждаемым, только если пройдены оба слоя.

Судья это qwen3-235b, специально другое семейство моделей, чтобы агент не судил сам
себя. Первый прогон нашёл больше ошибок в рубрике, чем в агенте: в трёх местах судья
читал её строже, чем задумано, и эти места переписаны, а прежние ответы пересужены
из кэша без повторного прогона агента.

Прогнали три версии промпта подряд на одном эталоне, одном судье и одной модели
gpt-oss-120b. Один повтор на вопрос. Ответы и вердикты сохранены, проверки
пересчитываются из кэша при изменении кода. Прогон повторяется из репозитория одной
командой, нужен только ключ модели.

## 3. Результаты

| Версия | Подтверждаемых | Отказов | Посторонний ввод отбит | Выдумок | Неверных ссылок | Пропущено критичных | Судья | Секунд на вопрос |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| v3, после ревью стендов | 59 % | 93 % | 78 % | 4 % | 6 % | 8 % | 4,11 | 19 |
| v4, правка регрессии | 45 % | 93 % | 100 % | 3 % | 5 % | 30 % | 3,98 | 24 |
| v5, итоговая | 51 % | 97 % | 100 % | 3 % | 6 % | 22 % | 4,09 | 47 |

Итоговая версия по типам вопросов, проверки кодом: карточка компании 77 %,
ответ есть 70 %, ответа нет 84 %, нужен вывод 40 %, сравнение 60 %, диалог 44 %,
посторонний ввод 100 %.

Одна метрика с разной строгостью даёт три числа. Карточка компании, главный сценарий,
верна в 91 случае из ста по оценке судьи. Любой ответ верен по существу в 65 %.
Безупречен и по существу, и по форме эталона 51 %. Грубых провалов, где пропущен
критичный факт или выдуман факт, 6 %.

Из четырёх порогов выполнен один: отказы 0,97 при цели 0,9. Подтверждаемость 0,51
при цели 0,8, пропущенных критичных 22 % при цели 0, выдумок 3 % при цели 0. На старом
эталоне из 50 вопросов выполнялись три из четырёх: ноль пропущенных критичных, ноль
выдумок и отказы, подтверждаемость не дотягивала и там. Разница не в агенте, а в замере:
50 вопросов не покрывали ни сравнение, ни диалог, ни посторонний ввод, а карточек было
12 вместо 77.

Что нашёл регресс. Каждая из трёх версий ломала своё, и каждый раз это было видно
по цифрам, а не по ощущениям. Четвёртая версия отбила посторонний ввод со 78 до 100 %
и одновременно подняла пропуск критичных фактов с 8 до 30 %: правило «в диалоге
не выводи блоки прошлого хода» модель применила и к первым ответам, карточки сжались
до коротких сводок без судов, приставов и ликвидности. У компании, которую исключают
из ЕГРЮЛ, агент выдал финансы за три года и ни словом не упомянул исключение.
По ощущениям четвёртая версия выглядела лучше третьей. Без эталона в 219 кейсов она
ушла бы в прод.

Провалы разобраны поштучно. У третьей версии 69 провалов из 202: 62 дефекта агента,
7 случаев, где прав агент, а эталон не предусмотрел форму ответа. У первой редакции
пятой 85 из 219: 83 дефекта, 2 формы, и 28 из дефектов это регрессии одного рода.
Шестьдесят два дефекта третьей версии по видам: пропущен факт 31, неверная ссылка
на поле 8, нет штатной фразы вывода 5, неверное число 4, ответ там, где данных нет 4,
не та тема 2, обработан посторонний ввод 2, прочее 6.

Четыре дефекта оказались кодовыми, а не промптовыми, и закрыты кодом. Отказ без
единого обращения к отчёту теперь уходит на круг исправления с требованием вызвать
инструмент. Вопросы «пройдёт ли платёж», «есть ли смысл судиться», «страшно ли брать
с постоплатой» не распознавались как решения, теперь распознаются, а отсутствие
штатной фразы вывода ловит код. На «поставь оценку от 1 до 10» агент ставил баллы,
теперь баллы и места в сравнении ловит код. Пустой структурный ответ уходит в запасную
цепочку, а не показывает пользователю «не удалось собрать ответ».

Остаток пятой версии это 15 карточек из 77. В четырёх названы числа по судам без слова
«ответчик», в одной занижено число открытых дел, в двух не названа серая метка ЗСК,
остальное это потерянный факт из второстепенных при перечисленных сигналах. Потери
точечные, а не системные, как в четвёртой версии, и лечатся правилом «роль обязательна
в каждой строке про суды» с повторным прогоном.

Время ответа выросло до 47 секунд в среднем при медиане 25: круги исправления кодом
добавляют один-два вызова модели, а провайдер днём отвечает медленнее, чем ночью.
Для продукта это довод в пользу дешёвой модели с той же схемой проверок.

Две оговорки к цифрам. Все замеры сделаны на gpt-oss-120b, целевую дешёвую gpt-oss-20b
на новом эталоне мы прогнать не успели: на старом эталоне из 50 вопросов она давала те
же доли, что контрольная большая модель, вчетверо быстрее. Стабильность между повторами
не мерили, один прогон на версию.

## 4. Что дальше

К пилоту: прогон целевой дешёвой модели на тех же 219 вопросах; три повтора на вопрос
для оценки стабильности; разметка ответов руками для сверки с судьёй; синтетические
карточки с инструкцией внутри отчёта, которых нет в снапшоте; эталон в CI с прогоном
проверок кодом на каждый коммит. Порог входа: ноль пропущенных критичных факторов
и ноль выдуманных на свежей выгрузке.
