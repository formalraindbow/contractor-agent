# Текущее состояние решения — 03.09.2026

## 1. Краткая аннотация

Мы разрабатываем AI-агента для проверки контрагентов. Пользователь вводит ИНН
или название компании, после чего агент анализирует банковский отчёт и формирует
краткую рекомендацию с подтверждающими фактами.

На текущем этапе работает backend-прототип для проверки одного контрагента:
система загружает и нормализует данные, рассчитывает риск-сигналы, предоставляет
их агенту через MCP-инструменты и программно проверяет ссылки на исходный отчёт.
Актуальная кодовая часть находится в ветке `develop`.

## 2. Проблематика

Пользователь — предприниматель малого бизнеса, которому перед сделкой с
незнакомой компанией нужно понять, можно ли работать с контрагентом и на каких
условиях.

Сейчас пользователь получает большой PDF и вручную сопоставляет финансовые
показатели, суды, исполнительные производства и государственные реестры либо
ограничивается итоговой меткой риска. При этом критические сведения могут
находиться вне готовых рекомендаций, а отсутствие данных легко принять за
отсутствие риска.

Проблема состоит не в нехватке данных, а в сложности их интерпретации и
превращения в понятное действие по сделке.

## 3. Актуальная постановка задачи

Необходимо создать AI-агента, который анализирует отчёт по одному контрагенту
и формирует понятный результат:

- существующие метки банка и ЗСК;
- дату формирования отчёта;
- 2–3 решающих факта;
- рекомендацию в форме условий взаимодействия;
- ссылки на поля, подтверждающие утверждения;
- явное указание отсутствующих данных;
- ответы на уточняющие вопросы только по входному отчёту.

Агент не должен пересчитывать метки банка, назначать собственный скор,
выдумывать отсутствующие сведения или принимать окончательное решение вместо
пользователя.

## 4. Выбранное техническое решение

Решение состоит из пяти слоёв:

```text
данные → сигналы → MCP-сервер → LangGraph-агент → API
```

- **Данные:** два снапшота с 200 карточками контрагентов.
- **Сигналы:** детерминированные правила по статусам, финансам, долгам, судам и
  налоговым признакам.
- **MCP-сервер:** восемь инструментов с единым контрактом ответа.
- **Агент:** LangGraph-граф из четырёх узлов — модель, инструменты, формирование
  структурированного ответа и проверка цитат.
- **API:** SSE-стриминг ответа и хранение контекста текущей сессии.

Все вычислимые показатели рассчитываются кодом. LLM используется для выбора
инструментов и формулирования ответа. Модель можно менять через конфигурацию без
изменения основной логики приложения.

Основной стек: Python, Pydantic, MCP, LangGraph, FastAPI, pytest и Docker.

## 5. Уже реализованные компоненты

- Загрузка и поиск по 100 JSON- и 100 CSV-карточкам.
- Нормализация разных форматов чисел и дат.
- Различение отсутствующей и пустой секции отчёта.
- Адресация исходных полей для проверки утверждений агента.
- Пять семейств риск-сигналов.
- Формирование рекомендации из трёх вариантов: «можно работать», «стоит
  проверить» и «работать с условиями».
- Сопоставление задолженности с чистыми активами компании.
- Восемь MCP-инструментов с единым форматом ответа.
- Агрегация больших списков исполнительных производств и судебных дел.
- LangGraph-агент из четырёх узлов.
- Программная проверка существования и значения цитируемых полей.
- API для запуска агента и потоковой передачи событий.
- Автоматические тесты без сетевых запросов и обращения к LLM.

Пользовательский интерфейс на текущем промежуточном этапе не реализован.

## 6. Предварительные результаты

- Все 200 карточек загружаются без ошибок.
- 63 519 адресов полей прошли round-trip проверку.
- По результатам правил 91 компания получила рекомендацию «можно работать»,
  80 — «стоит проверить», 29 — «работать с условиями».
- Система обнаруживает банкротство ООО «МАКСМАРКЕТ» при зелёных метках.
- Система обнаруживает предстоящее исключение ООО «РАДО АЛАТЫРЬ КС» из ЕГРЮЛ
  при отсутствии негативных признаков.
- В первом живом прогоне подтверждены 18 из 18 цитат.
- Ошибка модели при выборе рекомендации была обнаружена и исправлена
  автоматически.
- Полный ответ формируется за 34–54 секунды на платных моделях и до 150 секунд
  на бесплатной модели.
- Реализовано 166 автоматических тестов без сети и модели.
- По результатам адверсариального обзора найдено и закрыто 37 замечаний.

## 7. Ограничения

- Решение работает на тестовом снапшоте, а не на реальном API банка.
- Репрезентативность 200 карточек для всей клиентской базы не подтверждена.
- Пользовательский интерфейс пока не реализован.
- Эталонный набор вопросов и финальные метрики качества ещё не готовы.
- Влияние решения на retention не проверено на реальных пользователях.
- Полный ответ модели может занимать от 34 до 150 секунд.
- Риск-правила требуют дополнительной проверки кейсодателем или профильным
  экспертом перед использованием в продакшене.

## 9. План работ до финальной версии

1. Зафиксировать 30 вопросов и ожидаемые ответы для 10 карточек.
2. Разметить критические и некритические ошибки.
3. Реализовать автоматический judge по правилам `docs/CRITERIA.md`.
4. Прогнать вопросы несколько раз на двух моделях и собрать таблицу метрик.
5. Повторно проверить весь пайплайн на 200 карточках.
6. Реализовать пользовательский интерфейс с первым экраном и чатом.
7. Принять решение о включении батч-сравнения в финальную версию.
8. Провести экспертную приёмку с кейсодателем.
9. Подготовить финальное демо и материалы защиты.
