# Переход в evaluators: строгий trajectory match

Сценарии запускаются через фреймворк Alan `evaluators`, ветка
`codex/contractor-agent-evals` от `feature/judge-backend-switch` (`d8c5389`).
Проверена последняя локальная и сохранённая remote-ссылка; обновление remote
не удалось завершить, поэтому более свежие удалённые коммиты не исключены.

Агент — `openai/gpt-oss-20b`, независимый по семейству судья —
`z-ai/glm-5.3-flash`, оба через Polza. В каждом сценарии `trajectory_match`
использует **high (hard)**. Никакого автоматического отката к medium/low.

## Что измеряется

- **Trajectory match, 0–100**: исходная оценка судьи 0–1 × 100. Строгая сверка
  инструментов, аргументов, порядка и результата с эталоном. Цель — 85+.
  Среднее 85 не означает, что 85% ответов полностью корректны.
- **Сценарии с галлюцинациями, %**: число оценённых диалогов, в которых
  hallucination-судья дал меньше 1, делённое на число оценённых диалогов.
  Это частота сценариев с неподтверждёнными утверждениями, не доля выдуманных
  фактов и не `100 − средний score`. Проверяются все видимые ответы в диалоге.
- Ошибки API и судьи показываются отдельно с покрытием каждой метрики.
  Ошибка парсинга оценки не становится ни нулём качества, ни успешным ответом.
- Ручная вторая проверка остаётся обязательной выборкой фактических ответов:
  судья может ошибаться, особенно при переносе отсутствия записей на реальность.

## Корпус и эталон

Экспортировано 219 исходных кейсов (включая 77 карточек) и 16 новых сценариев
прямых ответов: **235 уникальных сценариев**. Повторы считаются отдельными
прогонами, а не новыми независимыми кейсами.

`evals/export_framework.py` строит YAML из версионируемого gold и инструментов
над исходными отчётами. Ответы тестируемой модели не используются как эталон.
Разметка `contractor-reference-v2-high` задаёт канонические чтения: сначала
идентификация, затем нужные разделы; отдельно проверены неизвестный ИНН,
неоднозначное имя, поиск по ОГРН, одна цель среди двух названных компаний,
владелец + связанные компании и сравнение ИП с ООО. Это разметка команды,
а не независимо согласованный банком набор эталонов. Для hard отличия
равноценных способов чтения тоже могут снижать оценку — такие случаи требуют
разбора, а не подгонки эталона под полученный ответ.

Диалоги воспроизводятся заданными репликами `fixed_queries`, без симулятора,
меняющего формулировки. Старые follow-up с синтетической памятью теперь
начинаются настоящей проверкой компании; это более строгий протокол,
поэтому старые проценты напрямую с новыми не сравниваются.

## Подключение

Локальный транспорт `evals.framework_bridge` вызывает тот же `AgentRuntime`.
Он отдаёт выполненные tool calls с аргументами и настоящие tool results,
а также видимый финальный ответ. Внутренние черновики и инструкции исправления
не являются ответом пользователю и не передаются судье как такие ответы.
Повторные tool calls после исправления сохраняются и оцениваются.

Мост слушает только `127.0.0.1:18102`; в публичный API он не добавляется.
Секреты остаются в `.env`, который не входит в Git.

```sh
# contractor-agent, окружение Polza задаётся через .env/переменные процесса
PYTHONPATH=src python -m evals.framework_bridge
# evaluators: один сценарий или весь корпус параллельно
EVAL_SCENARIOS_DIR=scenarios/cases/contractor pytest test_scenarios.py -k 'test_scenario_trajectory and direct-v8-03'
EVAL_SCENARIOS_DIR=scenarios/cases/contractor pytest test_scenarios.py -k test_agent_scenarios_parallel
```

Результаты: `.artifacts/<run>/latest/reports/`, `summary.json`,
`quality.json` и читаемый `quality.md`. Завершённый сценарий сохраняется
сразу, даже если остальные ещё выполняются. Для повторов используются
отдельные папки, чтобы одинаковые имена сценариев не перезаписывали друг друга.
