# v8: ответ на вопрос перед обоснованием

Статус на 7 сентября 2026: кандидат в ветке `codex/direct-answers`.
Полная проверка на живой модели не завершена, на публичный VPS кандидат не установлен.
Результаты v7 нельзя выдавать за результаты v8.

## Что меняется

На просьбу о рекомендации или выборе компании модель формулирует свою позицию первой:
кого предпочесть, почему отложить решение или почему никого не рекомендует на этих данных.
На вопрос о значении факта объясняет именно этот факт. Полная карточка остаётся отдельным
сценарием; запрос объяснения не должен повторять её целиком.

Модель получает компактные подтверждённые факты по компаниям текущего вопроса и возвращает
короткий ответ с идентификаторами выбранных оснований. Код выводит выбранные основания
буквально, со ссылками на исходные поля. В сравнении сохраняются основания по каждой
компании; при наличии критичных фактов в рекомендации не пропускается основной факт.
Зелёные метки не заменяют содержательного обоснования и не доказывают надёжность.

Существующие проверки сумм, исходных меток, источников и компании остаются. Новые проверки
ловят некоторые противоречия рекомендации фактам, повторяющиеся служебные подписи и
необоснованные утверждения о надёжности. Проверка не является доказательством смысловой
корректности произвольного текста: для этого нужны живые диалоги и экспертная оценка.

Старые сохранённые ответы отображаются без повторяющихся префиксов «Критический факт:»,
«Умеренный факт:», «Информация:», «Пробел:». Содержание сохранённой истории не переписывается.

- Перед выпуском: 20 сценариев с тремя повторами на выбранном провайдере 20B; затем
  исторический набор из 219 сценариев. Проверить вручную первые фразы рекомендаций,

  другое семейство моделей. Перед прогоном нужна калибровка судьи на заранее

## Как завершить проверку

Из рабочей копии кандидата после восстановления доступа к выбранному провайдеру:

```sh
PYTHONPATH=src .venv/bin/python -m pytest -o addopts='--import-mode=importlib' -m 'not live' -q
PYTHONPATH=src .venv/bin/python -m ruff check src tests evals
```

Конфигурация для Polza; `POLZA_API_KEY` читается из локального `.env`. Ключ создан с лимитом 300 ₽ в день и доступом только к GPT-OSS 20B и GLM 5.3 Flash.
Обе модели ответили на минимальный запрос. Калибровка судьи: 24/24 проверки прошли, ошибок API нет. Проверка трёх диалогов
агента ещё выполняется; это не приёмка кандидата. Артефакты: `runs/v8-polza/`. Каталог результата должен быть новым.
Судья использует отдельную модель и тоже расходует баланс. Тариф GLM 5.3 Flash
при проверке каталога: 9,08565 ₽ / 1М входных и 30,2855 ₽ / 1М выходных токенов
(https://polza.ai/models/z-ai/glm-5.3-flash). Цена зависит от выбранного провайдера.

```sh
JUDGE_BASE_URL=https://polza.ai/api/v1 JUDGE_MODEL=z-ai/glm-5.3-flash \
PYTHONPATH=src .venv/bin/python -m evals.paired \
  --env-file .env --models openai/gpt-oss-20b \
  --base-url https://polza.ai/api/v1 \
  --gold evals/suites/v8_direct_answers.yaml --suite all \
  --repeats 3 --concurrency 4 --judge \
  --out runs/v8-polza/direct-20b-complete --execute

JUDGE_BASE_URL=https://polza.ai/api/v1 JUDGE_MODEL=z-ai/glm-5.3-flash \
PYTHONPATH=src .venv/bin/python -m evals.paired \
  --env-file .env --models openai/gpt-oss-20b \
  --base-url https://polza.ai/api/v1 --suite all \
  --repeats 1 --concurrency 4 --judge \
  --out runs/v8-polza/full-20b-complete --execute
```

После правки кода или промпта результаты кандидата нужно отделить новым каталогом и
отпечатком исходников. Старые эталоны не менять ради прохождения: несовпадения буквальной
формулировки и ошибки смысла разбирать отдельно. Публичного провайдера не переключать
по результатам прогона на другом провайдере без проверки выбранной конфигурации.


## Судья v8

`evals/judge.py`, рубрика `v8-question-scope-1`: по явному запросу разрешена прямая
рекомендация на основании отчёта. Рекомендация не равна банковскому запрету или
ярлыку надёжности. Добавлено снижение за пересказ вместо ответа на вопрос;
узкий вопрос не требует полной карточки и всех компаний прошлого сравнения.
Инструкции внутри оцениваемых ответов и инструментов не должны управлять судьёй.
Это изменение критерия оценки, а не улучшение агента; старые и новые баллы нельзя
вычитать друг из друга как прирост качества.

`evals/calibrate_judge.py` содержит 12 заранее размеченных синтетических ответов:
рекомендация / пересказ, адрес / выдумка о мошенничестве, завершённые дела / текущий
долг, отсутствие прибыли / выдуманное число, выбор компании / перепутанные факты,
отказ на посторонний ввод / выполнение инъекции. Два повтора — 24 проверки.
Ожидаемые оценки и флаги не отправляются судье. Это проверка явных ошибок,
она не доказывает качество на всех реальных пограничных случаях.

В новых результатах `evals.paired` сбой судьи учитывается отдельно от ошибки агента,
а токены судьи записываются отдельно от токенов агента. Старые артефакты не изменяются.
