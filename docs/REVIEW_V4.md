# Ветка review-v4: изменения и сравнение

База: `develop`, commit `6c8a10a`. Работа ведётся в отдельном worktree `contractor-agent-review-v4`, ветка `codex/review-v4`. Исходный checkout и публичный стенд команды не переключаются.

## Что изменено

| Замечание ревью | Реализация |
|---|---|
| Неверная строка оставалась после очистки маркера | Сначала проверяем и удаляем утверждение по буквальной фразе, затем оформляем текст. Числовые фразы без цитаты также не публикуются. |
| Валидатор игнорировал знак и принимал любое совпавшее число | Учитывается знак, точность показанного округления; счётчики совпадают точно. Цитата на объект не подтверждает сумму. В сравнении обязателен свой ИНН. |
| Агрегаты не имели проверяемого адреса | `computed.*` пересчитывается чистыми инструментами. Раскрытие показывает результат и исходные поля. Это отдельный тип источника, не выдуманный путь в исходном отчёте. |
| Черновик становился видим до проверки | SSE отдаёт этапы инструментов и финальный ответ. Текст модели до проверки не транслируется. |
| В диалог попадал старый черновик и repair | История для следующего хода содержит только пользовательские реплики и реально показанные ответы. Журнал инструментов сбрасывается для каждого хода. |
| После нового неудачного поиска оставалась прежняя компания | Выбор очищается при новом поиске; отсутствие результата даёт явный отказ без старой карточки и даты. Точное совпадение названия имеет приоритет перед похожими. |
| Перезапуск сервера терял компанию при видимом старом чате | SQLite сохраняет весь контекст; стабильный идентификатор восстанавливает разговор после обновления страницы. Проверен цикл закрытия/повторного запуска приложения. Свежая выписка больше не обещается при отсутствии такого инструмента. |
| Короткие реплики и составные вопросы отсекались | Название, «Да», «Подробнее» доходят до агента. Тематический набор объединяет инструменты; налоги отделены от приставов. |
| Перестановка рекомендаций в сравнении | Блоки сравнения формируются из структурированных карточек с ИНН. |
| Отказ ошибочно определялся размером сводки | Размер ответа инструмента больше не считается доказательством наличия нужного поля. |
| Смысл отсутствующих финансовых полей менялся | Неизвестные обязательства не заменяются нулём. Источники пробелов ведут к существующему узлу. |
| Неполные записи роняли инструменты | Исправлена сортировка производств без даты; неизвестный статус не превращается в отсутствие производств. Проверены неполные финансовые строки. |
| Банковский негатив терялся при неполной сырой опоре | Для прибыли и арбитража проверяется соответствующий факт, не просто наличие раздела. |
| Автоматическая предоплата и выдуманное банкротство | Рекомендация нейтральна: «нужна дополнительная проверка перед взаимодействием». Терминальное основание берётся из конкретных сигналов. |
| Страница начиналась с большой карточки | Один чат, ввод названия/ИНН, список неоднозначных совпадений из результата поиска, сценарии бухгалтера, юриста и закупщика, боковая панель отчёта, основания, финансовые годы. Исправлена ширина 390 px, добавлены label, фокус и клавиатурное закрытие панели. |
| Предложенный промпт v4 | Применён и уточнён под буквальные цитаты и воспроизводимые расчёты. Цель меняет порядок объяснения; нет предположения о направлении платежа. |
| Повторы могли менять модель незаметно | Резервы по умолчанию выключены; журнал содержит фактические модели, число вызовов, использование токенов, задержку и fingerprint сборки. При ошибках генерации расход токенов может быть неполным: `usage_complete=false`. Счётчик вызовов отражает обращения LangChain; внутренние сетевые повторы SDK отдельно не считаются. Эти токены не равны гарантированному биллингу провайдера. |
| Неполный Docker image | В образ включён пакет `evals`. Проверяется состав wheel и изолированный импорт API. Docker daemon на этой машине недоступен, сам образ не запускался. |
| Невоспроизводимые эвалы | Кэш разделён по хешам кода, промпта, эталона и судьи; старые ответы не переписываются. Задержки агента и судьи разделены; ошибки включены в знаменатель успешности. Без судьи доля выдумок и оценка неизвестны, а не равны нулю. Удалённые цитаты черновика не считаются ошибками видимого ответа; явное отрицание «это не означает, что проверок не было» не штрафуется как утверждение. Проверяются отказы и совпадение вывода в тексте с карточкой. Ошибки учитываются также по типам вопросов и в стабильности повторов. |

Если модель не вернула допустимую структуру или не смогла исправить числа, ответ по финансам, судам, приставам и некоторым справочным разделам может быть сформирован кодом из тех же данных. В карточке сохраняются критические обстоятельства; пропуски не заменяются догадками. Это резервный способ сохранить полезный ответ. Для отсутствующих справочных разделов достаточно уже полученной сводки; название раздела филиалов соответствует схеме `branchesInfo`. В тексте ответа техническое `null` заменяется понятным отсутствием данных, а собственная рекомендация не называется «вердиктом банка». Полная смысловая проверка свободного текста не реализована; интерфейс этого и не обещает.

## Одинаковая модель и параметры

Для сравнения используется **gpt-oss-120b через Yandex AI Studio**, `temperature=0`, `reasoning_effort=low`, `max_tokens=4096`, timeout одного запроса 60 секунд, общий предел ответа 180 секунд, один сетевой повтор. В новой версии лимит графа повышен с 16 до 32 шагов: двум компаниям с последовательными инструментами и исправлением ответа нужен запас; общий таймаут сохраняется. Резервных моделей нет.

Qwen3.6-35B успешно вызвала инструменты, но на двух исходных прикладных запросах упёрлась в лимит генерации JSON. GPT-OSS-120B на этих же запросах завершила ответы. Это проверка совместимости и небольшой пилот, не полный рейтинг моделей. Модель в собственном контуре, ресурсы GPU и независимое экспертное качество требуют отдельного испытания.

Официальный каталог: https://aistudio.yandex.ru/en/docs/ai-studio/concepts/generation/models

Локальный `.env` содержит существующий Yandex API key; ключ и идентификатор каталога не добавляются в примеры конфигурации. Оба процесса используют один конфиг новой ветки. Оригинальный `.env` не изменён.

## Запуск

Из worktree новой ветки:

```bash
uv sync --frozen
git worktree add --detach ../contractor-agent-baseline-6c8a10a 6c8a10a
uv run python scripts/serve_comparison.py start --baseline ../contractor-agent-baseline-6c8a10a
```

- Базовая версия: http://localhost:8081
- Новая версия: http://localhost:8082

Если worktree уже существует, повторять `git worktree add` не нужно. Сервисы слушают только loopback. Их конфигурация доступна на `/v1/comparison/config`. Внешний адаптер добавляет одинаковое наблюдение за вызовами LLM обеим версиям, не меняя текст ответа, промпт, маршрутизацию или инструменты базовой версии.

```bash
uv run python scripts/serve_comparison.py stop
```

Останавливаются только PID, записанные этим launcher, после проверки команды процесса. Для загрузки изменений Python нужно остановить и снова запустить стенды.

## Сравнение

```bash
# 15 сценариев, 20 реальных ходов на каждую версию
uv run python scripts/compare_branches.py --repeats 2
# Исходный набор из gold.yaml
uv run python scripts/compare_branches.py --gold
```

Каждый запуск создаёт новый каталог `runs/ab-<дата-время>/`: `manifest.json`, сырые SSE-события, ответы и результаты каждого хода, `summary.json`, `report.md`, `report.html`. HTML показывает ответы рядом. Сессии версий изолированы; одинаковые ходы выполняются в одном порядке. Сравнение проверяет совпадение настроек до запуска. Данные не меняются.

Сценарии покрывают поиск по названию, неоднозначность, отсутствие компании после успешного поиска, смену ИНН, составные темы, налоги, знак прибыли, неизвестную численность и суммы, разные судебные статусы, перестановку сравнения, роль бухгалтера, продолжение разговора и отсутствие раздела.

В режиме `--gold` вопросы-продолжения получают реальный предшествующий запрос о компании в обеих версиях. Подготовительные ответы сохраняются в `setup-*.json`; метрики относятся к целевым вопросам и не включают эти подготовительные вызовы.

Результат regex-проверок — диагностическая приёмка этих сценариев. Он не заменяет экспертную оценку всех чисел, смысла и полноты ответа. Сравнение по 20 ходам недостаточно для вывода о стабильности продакшна. В `gold.yaml` сохранены вопросы о направлении платежей, но ожидания синхронизированы с нейтральной политикой: предоплата не считается универсальным безопасным условием, исключение из ЕГРЮЛ не подменяется банкротством. Старые кэши с новой рубрикой не объединяются. Полный прогон этого набора ещё не выполнен; приведённое парное сравнение использует отдельный `comparison.yaml`.

## Границы этой ветки

Веб-поиск новостей, скоринг всей базы, новые GPU-инстансы и переписывание на React из раздела «идеи» не добавлены: они меняют источник данных или существенно расширяют продукт и не нужны для проверки предложенных исправлений. Презентации и организационные договорённости с кейсодателем остаются отдельной работой команды.

Сессии сохраняются в SQLite (`runs/sessions.sqlite3`, для стенда — внутри `runs/comparison-servers/review-v4/`). Сохраняются сообщения, выбранные ИНН, цель и ожидаемое уточнение. Ссылка `?chat=…` и идентификатор в sessionStorage позволяют восстановить разговор после обновления страницы. `SESSION_DB_PATH` задаёт путь, `SESSION_STORE=memory` явно включает временную память для экспериментов. На вопрос о свежей выписке помощник объясняет отсутствие доступа к ФНС и показывает статус из имеющегося отчёта. Проверен реальный цикл закрытия/открытия приложения и продолжение без повторного ИНН.

SQLite рассчитан на этот локальный стенд с одним процессом. Для развёртывания добавлен общий PostgreSQL checkpointer: отдельная миграция, защита от одновременной записи в один чат разными репликами и readiness с проверкой базы. Compose хранит БД в именованном томе; пример Kubernetes подключает внешнюю БД. Подробности и проверки перезапуска — в [SESSION_STORAGE.md](SESSION_STORAGE.md). Для банковского контура остаются авторизация с проверкой принадлежности сессии пользователю, политика хранения, резервное копирование и нагрузочные испытания. Сам UUID чата не заменяет авторизацию. [Документация LangGraph о постоянной памяти](https://docs.langchain.com/oss/python/langgraph/persistence).


## Доработка интерфейса после сравнения

Стартовый экран стал компактнее: убран декоративный заголовок над основным, уменьшена типографика и расстояние до ввода. Вместо незавершённых заготовок про роли — два конкретных вопроса по демобазе, которые сразу запускают проверку. Поле ввода начинается с одной строки и растёт до 140 px.

История прокручивается внутри своей области, поле ввода остаётся на месте. Отправка переводит к новому вопросу, получение ответа показывает его начало. Ручная прокрутка вверх во время ожидания отменяет автоматический переход; возврат вниз снова включает его. Доступна кнопка «В конец диалога». Подсказки продолжения остаются только у последнего ответа, повторная кнопка оснований убрана.

Проверено в браузере: 1280×800, 390×844 и низкое окно 844×390; горизонтального переполнения нет, поле ввода доступно. На живом диалоге МАКСМАРКЕТ проверены запуск примером, переход к следующему вопросу, сохранение позиции при чтении старого ответа, возврат вниз, восстановление страницы и рост многострочного ввода. Проверка синтаксиса JavaScript и форматирования прошла. Серверные алгоритмы в этом изменении не менялись, результаты сравнения выше относятся к зафиксированной сборке.

Во время проверки прокрутки выявлен дополнительный пример ограничения модели: на составной вопрос о финансах, судах и производствах МАКСМАРКЕТ ответ ошибочно назвал финансовые показатели отсутствующими и оставил служебные имена полей. Это не эталонный ответ; пример сохранён в локальном диалоге `ui-layout-sept05` для дальнейшей проверки качества. Изменение интерфейса не устраняет этот содержательный дефект.
