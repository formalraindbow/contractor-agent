# Что сделано по коду к 3.09 — заготовка для презентации

Блоки — по слайду. Формулировки короткие, под них — цифры и цитаты для речи.

## Слайд: статус одной строкой

**Сквозной прототип работает:** вопрос об ИНН или названии → агент через инструменты читает отчёт банка → риск-сигналы считаются правилами → карточка-рекомендация с фактами, у каждого — адрес поля в отчёте, проверенный программно.

Чекпоинт программы («агент читает данные и отвечает по одному контрагенту») закрыт в четверг вместо пятницы.

---

## Слайд: архитектура — пять слоёв

```
данные  →  сигналы  →  MCP-сервер  →  агент (LangGraph)  →  API + интерфейс
снапшот    правила      8 инструментов   4 узла, проверка цитат   SSE-стриминг, чат
200 карт.  кодом        единый контракт   память сессии           Docker
```

- Модель нигде не считает — только формулирует. Всё, что можно посчитать кодом, считается кодом.
- Агент не читает файлы — только инструменты. В банке на месте наших данных встанет их API, контракт тот же.
- Модель — за одной строкой конфига: проверено на трёх (OpenRouter платно и бесплатно, Яндекс-облако), код не менялся.

## Слайд: данные — что сломано и как закрыто

- Два файла — **разные** 200 компаний, не один набор в двух форматах.
- Числа в обёртках MongoDB (16 путей), суммы строками, две схемы дат, даты до 2014 года в UTC+4, кириллическая «а» в коде признака.
- «Секции нет» ≠ «секция пуста» — оба состояния реальны, различаются на уровне типа.
- Каждое поле имеет адрес `report.executionProceedings[3].amount` — фундамент проверки цитат.

Цифры: 200 карточек загружаются без единой ошибки · 63 519 адресов полей проверены round-trip · более 30 неточностей исходных документов найдены и исправлены независимой разведкой по данным.

## Слайд: сигналы — чек-лист в коде

Пять семейств: статус и реестр · финансы · долги у приставов · суды · признаки налоговой из отчёта банка.

- Тяжесть долгов — **относительно чистых активов**, не в рублях (по слову кейсодателя): 180 тыс. долга при капитале 10 тыс. — критично, 25 млн при 460 млн — нет.
- «Нет данных» никогда не превращается в «нарушений нет»: отдельный список пробелов с причиной.
- Рекомендация из трёх исходов считается кодом и проверяется на всех 200 компаниях без модели.

Цифры: по 200 компаниям — 91 «можно работать» / 80 «стоит проверить» / 29 «условия» · три правила совпали с признаками банка компания в компанию (убыток 10 = 10, производства 33 = 33) · банкрот с зелёной меткой (МАКСМАРКЕТ) и исключение из ЕГРЮЛ при нуле негативов (РАДО АЛАТЫРЬ КС) ловятся.

## Слайд: агент — четыре узла и защита от выдумок

```
agent (модель + инструменты) → tools → finalize (структурированный ответ) → validate (проверка цитат)
```

- Карточку — вердикт, факты, пробелы, метки — собирает **код** из сигналов; модель пишет только текст и цитаты.
- Валидатор сверяет каждую цитату с отчётом: адрес существует, число совпадает. Один круг на исправление, потом невалидное помечается и не показывается как факт.
- Первый живой прогон это доказал: модель написала «стоит проверить» там, где сигналы дают «условия» — поймано и исправлено автоматически.

Цифры: 18 из 18 цитат первого ответа подтверждены · полный ответ по компании — 34 с (Яндекс `deepseek-v4-flash`), 54 с (`gpt-oss-20b`), 150 с (бесплатная модель).

## Слайд: MCP и API — контракты для команды и для банка

- 8 инструментов MCP с единым конвертом `{available, data, source_paths, report_date}`; `available: false` с причиной вместо пустого списка; длинные списки — сводками (1744 производства → 10 крупнейших + агрегат).
- Тот же сервер подключается к Claude Desktop — готовый конфиг в репозитории.
- API по SSE-контракту: события «агент работает», текст по токенам, итоговый структурированный ответ; история сессии; ручки для виджетов; страница чата; Docker compose.

- 166 автотестов без сети и без модели: все 200 карточек, демо-карточки, синтетика под настоящий API банка.
